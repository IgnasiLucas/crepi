Preparation of SNP genotypes in Nexus format

J. Ignacio Lucas Lledó

2026-03-05

For the purpose of Bayesian species delimitation, with SNAPPER (Stoltz et al. 2020), we need to prepare the input file, which should be a Nexus file with SNP genotypes. Actually, I advance that we have several options for generating a matrix of SNP genotypes, and I think it’s better to prepare more than one data set and run the same analysis on all them, to check for robustness.

Calling genotypes with ANGSD

At least, we have two sets of BAM files: those aligned to the reference genome in 2023-05-18/BAM, and those aligned to the set of ddRAD loci, in 2024-10-04/BAM.

We already have selected variable sites with limited linkage disequilibrium and with a minimum number of 60 samples with at least 2 reads covering the site. And we have the genotype likelihoods of those sites in ../2024-03-11/Likes2/ARCTIC.beagle.gz. However, for some reason, ANGSD does not do the job when provided with the list of sites and the genotype likelihoods. We have to feed it the raw BAM files and compute the likelihoods all over again. I will filter later.

The method implemented by Stoltz et al. (2020) is based on that of Bryant et al. (2012), where the authors explain very well how they compute the likelihoods. It turns out that the genotypes are turned to allele frequencies. The model assumes a Fisher-Wright population mating at random, but it does not model it explicitly. So, the important information in the data is not the distribution of genotypes, but the allele frequencies. Actually, the data file provided as an example suffers from a severe lack of heterozygotes. Thus, it is not essential to get accurate genotypes. SNAPPER would probably work equally well on haploids, or with a random sample of a single allele per site per individual. Thus, I should not be worried about some heterozygotes being called homozygous when coverage is low. I could use a low coverage threshold. But we do not need too many sites.

When calling genotypes another important argument is the posterior probability cutoff. If the three possible genotypes were equally probable, the posteriors would be 0.33, and a cutoff at that level would produce no missing data at all, but would introduce noise. I am willing to confound a heterozygote for any of the homozygotes (with equal probability). But I am not willing to confound the two homozygous genotypes. I will try with a cutoff of 0.75, and see how much missing data we get.

Another consideration is whether to use only variable sites or also the invariable ones. SNAPPER allows both. However, the interpretation of time units when using only variable sites is unclear: perhaps, expected number of mutations per site, knowing the site is variable? Such units are impossible to relate to estimates of mutation rate. In addition, once we get the most a posteriori probable genotypes, we may want to re-estimate nucleotide diversity measures, which require invariable sites.

Yet, another consideration is Hardy-Weinberg equilibrium. After having run the F\(_{ST}\) analysis several times in folder 2024-10-10, I realized several sites far from HWE seem to be collapsed paralogy, and I think it’s good to remove them. However, I am not separating individuals by population or putative species when calling genotypes. Thus, HWE does not apply.

I still need to remove positions in close linkage from others. The strategy is to use the distances among adjacent loci. Such distances are mostly short within a locus, and eventually larger among different loci. Thus, I can assign a locus to every position and then select one SNP (with highest MAF) per locus. I arbitrary set the distance threshold to 1000, beyond which the SNPs are assigned different loci. Of course, they are also different loci if they are in different contigs.

library(plyr)
MaxDist <- 1000
numloci <- dim(genoVar)[1]
lociVar$dist <- c(NA, lociVar[2:numloci, 'pos'] - lociVar[1:(numloci-1), 'pos'])
lastcontig <- c('contig_null', lociVar[1:(numloci - 1), 'contig'])
lociVar[lociVar$contig != lastcontig, 'dist'] <- NA
rm(lastcontig, numloci)
lociVar$locus <- cumsum(is.na(lociVar$dist) | lociVar$dist > MaxDist)
lociVar$n <- rowSums(! is.na(genoVar))
selected <- ddply(lociVar, .(locus), function(x) x[which.max(x$freqs * x$n),])
selIndex <- match(paste(selected$contig, selected$pos, ":"),
                  paste(lociVar$contig, lociVar$pos, ":"))
selGeno <- genoVar[selIndex,]
GenoStrings <- sapply(selGeno,
                      function(x) {
                         x[is.na(x)] <- '-'
                         paste0(x, collapse = '')
                      })
write('#NEXUS',
      file = 'toRef.nex')
write('BEGIN Data;',
      file = 'toRef.nex', append = TRUE)
write(sprintf('\tDIMENSIONS NTAX=%i NCHAR=%i;',
              length(GenoStrings), nchar(GenoStrings[1])),
      file = 'toRef.nex', append = TRUE)
write('\tFormat datatype=integerdata symbols="012" missing=-;',
      file = 'toRef.nex', append = TRUE)
write('\tMatrix',
      file = 'toRef.nex', append = TRUE)
write.table(data.frame(Sample = names(geno), Genotypes = GenoStrings),
